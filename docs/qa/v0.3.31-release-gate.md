# Clench Wallet 0.3.31 candidate gate

Maintenance candidate for the eight findings in the September 16 v0.3.30 audit.
This document is a gate, not a declaration that a release has been published.
Exact final-source receipts belong in CI artifacts and external execution status,
not in a tracked document requiring its own commit hash.

## Required automated acceptance

- AUD-01: reject extra/malformed/duplicate cosigner keys before persistence;
  actual ViewModel, repository, native receive/change policy and Room tests.
- AUD-02: exact nonempty passphrases agree across preview/import/unlock and
  restart; whitespace and Unicode cases; no silent existing-wallet rewrite.
- AUD-03: wallet-local metadata and lossless Room13-to-14 upgrade; every supported
  old migration route, encrypted reopen, interruption/rollback, offline restore,
  duplicate/invalid mapping and colliding-wallet regressions.
- AUD-04: actual native selected inputs exclude wallet-scoped freezes for
  hot/watch-only, single/batch/drain, PSBT, RBF and applicable CPFP paths;
  metadata failure fails closed, including retained drafts and legacy aliases.
- AUD-05: offline admission at HTTP and Electrum boundaries, including reused
  connections and delayed callbacks; cancellation/toggle/recovery tests.
- AUD-06: real activity NFC callback containment, valid-input control, locked and
  cold/warm behavior; parser rejection is preserved.
- AUD-07: real PIN/system authentication success/cancel/background and recreation
  with unchanged seed/send gates; stale authorization cannot weaken relocking.
- AUD-08: native chain state wins over stale display confirmation caches;
  partial/failed/repeated sync and reorg/reconfirmation acceptance retained.
- Full JVM suite, debug/test/unsigned release compilation, lint, CodeQL,
  release-control tooling, committed schemas and 5,000/20,000 hostile-input
  execution markers. Skipped, queued, compiled-only and missing cases are not passes.
- Fresh BDK and SQLCipher cross-version persistence phases; exact native inventory,
  strict Gradle verification, Maven advisory scan and reviewed source-bound Cargo
  dispositions. No dependency modernization is included merely to close the audit.
- Independent changed-path review with all material findings resolved.

## Required device acceptance and release boundary

Changed-path physical acceptance is **NOT RUN** at preparation time: passphrase
lifecycle, effective multisig policy, database upgrade/import isolation, frozen
drafts, offline toggle, NFC containment and relock authorization on a disposable
device/profile. Physical TAPSIGNER/Coldcard/SATSCARD, API/OEM/ABI and signed-app
checks must name the exact source/APK and hardware actually tested. Existing
unchanged-path deferrals do not create a waiver for these changed paths.

Do not tag or publish until required automated, review and applicable manual
acceptance is recorded, or an explicit applicable maintainer decision exists.
Use the existing trusted Mac SSH source-tag key; production APK signing remains
in the protected source-free GitHub job. Preserve required checks/reviews and
independent A/B/C source builds. No force-moved tags or replacement signing keys.

After publication independently verify the exact public 13-file asset contract,
signature continuity, checksums, attestations, SBOM and native/source payload
comparison. Then update and actually deploy the website, preserve mail
autoconfiguration, and verify plain `/` and `/index.html` without a query string.

## Recovery and assurance limits

Schema14 preserves surviving metadata rows. It cannot recover metadata already
lost by an earlier overwrite. Do not downgrade an upgraded database into an old
APK or clear it to force startup: retain a backup and use a forward fix. Existing
wallet descriptors and passphrase identities must not be rewritten automatically.

This is scoped remediation, not whole-product audit sign-off. SQLCipher vendor
source correspondence, deeper native C coverage and unfinished wallet review
remain separate assurance work; physical results are never inferred from CI.
