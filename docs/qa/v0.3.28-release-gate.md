## Release-secret governance residual

The four Android signing values are configured as GitHub repository secrets,
not environment secrets. The current trusted workflow injects them only into
the `release-signing` environment job after approval and does not expose them to
the build or verification jobs. This preserves the runtime isolation used by
v0.3.27, but it is weaker governance than storing the values at environment
scope. Move or rotate them into environment-scoped secrets when the maintainer
can safely re-enter all four values, then delete the repository-scoped copies.
Do not weaken or bypass the current approval boundary in the meantime.
