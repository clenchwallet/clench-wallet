# Clench Wallet 0.3.22

Clench Wallet 0.3.22 is a production security and verification release. It adds
fail-closed protocol boundaries, a deterministic hostile-input verification
laboratory, and independently checkable release evidence.

## In plain English

- Existing hardware-wallet signing is **not blocked**. Clench creates a PSBT,
  you move it to a supported signer by QR, an intentional NFC tap, or a file,
  and Clench checks the returned transaction before asking you to broadcast.
- Clench does not implement a direct hardware-wallet data connection over USB
  or Bluetooth. A signing device may still use USB for power.
- TAPSIGNER setup, identity verification, xpub import, address verification,
  multisig policy import, and encrypted backup are available. This version
  cannot yet ask TAPSIGNER to sign a payment. That is a temporary software
  limitation, not a claim that single-signature TAPSIGNER wallets are unsafe.
- SATSCARD uses a dedicated verified unseal-and-sweep flow. It is not presented
  as an arbitrary PSBT signer.
- Real-device SATSCARD, TAPSIGNER, and hardware-wallet round trips were
  explicitly deferred for this release. Simulator results are not labeled as
  physical-device passes.

Version 0.3.22 still declares two unused Bluetooth permissions even though it
contains no Bluetooth wallet transport. Source for the next update removes
those declarations and adds a release-control check that prevents them from
returning.

## Wallet and protocol hardening

- Structurally preflights every imported or phone-signed PSBT before BDK parsing, with bounded size, canonical CompactSize, duplicate-key, truncation, and framing checks.
- Rejects mixed, conflicting, excessive, malformed, or decompression-bomb BBQr streams while preserving generic animated-QR compatibility.
- Rejects ambiguous or checksum-conflicting Coldcard NDEF signing messages and bounds all NFC text/binary records before decoding.
- Bounds and validates SATSCARD and TAPSIGNER NFC responses, canonical/depth-bounded CBOR roots, duplicate keys, typed fields, certificate chains, nonces, public keys, slots, derivation paths, delay values, and response sizes.
- Rejects duplicate multisig cosigners even when origin metadata or branch aliases differ.
- Makes pending signing authorization atomic and single-use across concurrent, cancelled, or interrupted signing flows.
- Fails closed on negative, non-finite, overflow-shaped, excessive absolute, and excessive relative fee metadata.
- Hard-bounds every blocking/native Electrum entry point, closes transports
  before cancellation, closes connections that finish after timeout, and
  serializes every shared native Wallet/Persister lifecycle operation.

## Verification laboratory

- Adds reproducible, seeded property and hostile-corpus tests for PSBT, BBQr/QR, Coinkite APDU/CBOR, multisig descriptors, storage corruption boundaries, fee attacks, interrupted signing, and recovery rollback.
- Adds deterministic SATSCARD and TAPSIGNER response simulators. They exercise parser and interruption behavior but do not claim to emulate RF timing, secure-element cryptography, or physical cards.
- Runs 1,024 generated cases per property suite in hosted Android CI and release gates, plus a weekly no-secrets 5,000-case hostile-fuzz lane. Local case counts are configurable with `CLENCH_FUZZ_CASES`.

## Release evidence

- Pins the Gradle distribution by SHA-256, validates the wrapper JAR and pins every third-party action by commit in every hosted lane, and uses a versioned Ubuntu runner image.
- Generates a deterministic CycloneDX 1.6 SBOM for all locked release-runtime components, including every available Gradle-verified artifact SHA-256.
- Publishes deterministic in-toto/SLSA provenance evidence covering the APK, SBOM, source identity, toolchain, workflow, dependency locks, and verifier scripts.
- Creates and independently verifies GitHub Sigstore provenance and exact CycloneDX SBOM attestations.
- Rebuilds the unsigned release APK in a separate no-secrets job and requires its payload, compressed bytes, relative order, local ZIP metadata, and archive comment to match the signed APK exactly, excluding only actual v1 signature metadata.
- Enforces that signing credentials exist only in the protected signing job, are destroyed before attestation and upload, and never enter independent verification or publication jobs.

## Verification boundary

Automated tests and clean no-secrets rebuilds cannot prove physical NFC/RF
behavior, secure-element behavior, camera behavior, or third-party hardware
firmware compatibility. The exact remaining device gates are recorded in
`docs/qa/physical-hardware-gates-v0.3.22.md`. The authorized ship decision and
explicit physical-hardware deferral are recorded in
`docs/qa/v0.3.22-release-gate.md`.

Sanitized live Testnet3 lifecycle evidence, including the confirmed RBF
replacement, confirmed faucet return, and honest cancel/CPFP timing boundary, is
recorded in `docs/qa/testnet-lifecycle-v0.3.22.md`.

The maintainer authorized this release on 2026-07-27 UTC with an explicit
physical-hardware deferral. SATSCARD, TAPSIGNER, hardware-wallet PSBT,
independent-hardware multisig, representative physical Android NFC/camera,
hardware-backed Keystore, biometric, upgrade, process-kill, and removable-media
tests remain `NOT RUN`; simulator and emulator results are not physical passes.
