# Clench Wallet 0.3.29

This release hardens authentication settings, multisig policy validation,
signing-session recovery, backup imports and network input handling. Existing
wallets are preserved; no signer key rotation or destructive database migration
is introduced.

## Security corrections

- Turning off an enabled seed-view or send authentication requirement now
  requires fresh crypto-bound Android authentication. Cancelling or losing the
  authenticator does not turn protection off. Initial setup initializes only
  previously unset gates before any wallet exists.
- New multisig policies reject equivalent extended public-key material even
  when origins or serialization metadata differ. Existing wallets are not
  rewritten or blocked; Wallet Info and descriptor backups warn about repeated
  key material. Different keys do not prove independent human/device ownership.
- Phone signing reserves the exact reviewed transaction before authentication
  and ignores stale callbacks. Hardware signing sessions can explicitly discard
  collected signatures and restart from the unchanged original PSBT with fresh
  review. Conflicting signatures are not silently overwritten, and broadcast
  remains separate.
- State backups reject unsafe or duplicate wallet identifiers before database
  work. Valid existing IDs and associated labels/UTXO metadata are retained.
- Legacy multipart QR rejects conflicting duplicate frames and count changes.
  Electrum helpers bound line/cumulative inputs and close sockets on exit.
  SATSCARD decrypted-key buffers are cleared on validation failure before handoff.

## Database and release controls

SQLCipher updates from 4.15.0 to 4.17.0 without changing compileSdk 36 or AndroidX
SQLite 2.6.2. Disposable-emulator tests cover a pinned old-version writer,
new-version reader, committed WAL recovery, wrong-key/corruption nonmutation
and new-process reopen. Strict dependency locks and checksums are retained.

The original APK signing credentials are now restricted to the protected
`release-signing` environment; repository-scoped copies are removed. Original
key/password and certificate continuity were validated on the maintainer Mac,
and secret scope and protections were independently checked through metadata.
No remote secret-content readback is claimed.

Native-bearing artifacts now have a pinned inventory and a live pre-sign Cargo
advisory gate. Seven candidate advisory IDs across four groups have reviewed
Android call-path dispositions, not patched-version claims. Reviews expire and
invalidate on application, artifact, lock, evidence or advisory changes; new
findings and failed lookups block signing. Raw findings remain visible.

## Evidence and limits

The remediation branch has 475 passing JVM tests and 22 named hosted Android
regressions, including five actual Android authentication-UI cases, plus the
separate cross-version database phases. Final-candidate CI, lint, fuzz,
instrumentation and release checks are required again before publication;
compilation alone is not a runtime pass. Exact results belong in
`docs/qa/v0.3.29-release-gate.md`.

This was a scoped remediation of an interrupted audit, not a completed
whole-product or external professional audit. Native vendor binaries were not
independently rebuilt. SQLCipher's Android source tag pins an older core
submodule than its published 4.17.0 artifact reports; that vendor provenance
discrepancy remains open despite passing upgrade tests. C advisory coverage is
incomplete and must not be inferred from a clean Maven result or the Cargo
applicability gate. See `docs/security/native-assurance.md`.

No new physical NFC/card, camera, hardware-wallet, OEM-specific or signed-APK
on-device acceptance is claimed. The Mac strict build passed for the earlier
remediation commit; its emulator never reached Android, so Mac runtime checks
remain NOT RUN. Existing physical hardware deferrals remain explicit. Clench
does not add USB or Bluetooth signer data connections. SATSCARD remains
fund/verify/unseal/sweep-only.

The release preserves the pinned APK signer, signed source-tag requirement,
isolated signing job, independent unsigned rebuilds, complete APK payload
comparison, SBOM/provenance attestations and exact public asset contract.
