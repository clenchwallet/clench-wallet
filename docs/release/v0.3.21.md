# Clench Wallet 0.3.21

Clench Wallet 0.3.21 fixes the end-to-end Clench phone-signer multisig workflow and improves F-Droid discovery metadata.

## Multisig workflow

- Normalizes the account-level wildcard returned by BDK before Clench appends external and change branches, preventing invalid `/*/0/*` and `/*/1/*` descriptors.
- Adds regression coverage for generated account keys and standard P2WSH multisig witness-size estimation.
- Estimates the final signed virtual size of standard multisig PSBTs, using present signature lengths and a safe maximum for missing signatures.
- Labels estimated final fee rate and virtual size explicitly on transaction review screens.
- Keeps incomplete multisig PSBTs blocked from broadcast.

## Authentication usability

- Detects when Android biometric or device-credential authentication is unavailable during onboarding.
- Explains that seed-view and transaction-signing authentication gates will be disabled so the wallet remains usable.
- Prevents unavailable gates from being enabled in Security settings while still allowing an existing gate to be turned off.
- Gives existing users an actionable route to Settings when phone signing cannot authenticate.

## F-Droid discovery

- Uses the exact phrase “Bitcoin wallet” in the localized short and full descriptions.
- Keeps the short description within F-Droid's 80-character limit and highlights non-custodial multisig support.

## Verification boundary

The release candidate passed unit tests, lint, debug assembly, and Android 16 / API 36 emulator checks. A fresh testnet setup created a 2-of-2 phone-signer wallet, and a funded wallet built and phone-signed a testnet PSBT with an estimated final fee review. The incomplete PSBT was intentionally not broadcast and was safely refused by the broadcast action. Physical hardware-signer acceptance remains a separate release gate.
