# Clench Wallet 0.3.20

Clench Wallet 0.3.20 is a security and release-trust update. It hardens how wallet secrets, recoverable wallet state, transaction approvals, fees, PSBTs, network connections, dependencies, and signed releases are handled.

## Security and wallet safety

- Preserves encrypted wallet secrets on storage or keystore errors instead of deleting them.
- Quarantines unreadable BDK wallet state and provides an explicit recovery/rescan path.
- Invalidates signed transaction proposals after edits and requires review of immutable final outputs, fees, change, and transaction identifiers.
- Applies the same review and authentication policy to send, sweep, fee bump, cancel, phone signer, hardware signer, SATSCARD, and multisig paths.
- Adds absolute, relative, and fee-rate safeguards based on the constructed transaction.
- Compares complete unsigned PSBT transaction templates, including version, locktime, and sequences.
- Fails closed on invalid TLS pins while retaining hostname verification.
- Bounds QR, file, NFC, PSBT, and backup imports and parses BIP21 amounts exactly.
- Keeps protected application content out of composition while the wallet is locked.

## Recovery and signing experience

- Adds an in-app BIP39 word picker that avoids sending recovery words through the system keyboard.
- Redesigns sweep as Source → Discovery → Destination → Fee → Review.
- Unifies transaction review across software and hardware signing flows.
- Adds device-specific hardware-signing progress and clearer connection/signature status.
- Adds guided wallet-state quarantine, scan-depth selection, verification, and cleanup.
- Routes offline actions to connection setup with an explanation instead of leaving them silently disabled.

## Release and dependency trust

- Protects release signing with a reviewed GitHub environment and separates signing from publishing.
- Requires immutable action SHAs, signed annotated release tags, strict Gradle dependency verification, APK checksums, signer-certificate reporting, and build-provenance attestations.
- Adds CodeQL and committed Room migration schemas/tests.
- Updates Android Gradle Plugin to 9.2.1, Kotlin coroutines to 1.11.0, and the complete CameraX family to 1.6.1 with coordinated lock and verification metadata.

## Verification boundary

Automated tests, emulator checks, and software-testable signer protocols do not replace physical-device acceptance. Before publishing, use the release gate in `docs/qa/v0.3.20-release-gate.md` and verify physical SATSCARD, TAPSIGNER, supported hardware-wallet transports, multisig threshold signing, and a live testnet transaction lifecycle.
