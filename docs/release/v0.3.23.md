# Clench Wallet 0.3.23

Clench Wallet 0.3.23 is a transport-privacy and hardware-wallet clarity
release. It removes permissions the app did not use, strengthens TAPSIGNER
setup verification, and makes the supported signing paths easier to
understand.

## In plain English

- Clench no longer requests Bluetooth scan or connection permissions and does
  not advertise Bluetooth Low Energy hardware.
- Clench does not communicate with signing devices through USB or Bluetooth
  data connections. Transactions move by QR, an intentional NFC tap, or a
  user-selected file/removable card. A signer may still use USB for power.
- Existing supported hardware-wallet PSBT round trips remain available. This
  release removes only unused permissions and misleading transport labels.
- Coldcard Mk4/Mk5 guidance now recommends NFC or a user-selected microSD/file
  flow instead of presenting Virtual Disk as a Clench transport.
- TAPSIGNER setup now verifies that the master xpub contains the exact fresh
  chain code Clench supplied to the card.

## TAPSIGNER and SATSCARD boundary

TAPSIGNER setup, factory-certificate verification, xpub import, address
verification, multisig policy import, and encrypted backup remain available.
Direct TAPSIGNER payment signing is not implemented in this release. The
imported wallet is watch-only in Clench until authenticated signing, PIN/CVC
change, PSBT signature injection, finalization, and real-card tests are
complete.

SATSCARD retains its dedicated certificate-verified, CVC-authenticated
unseal-and-sweep flow. It is not presented as a general PSBT signer.

The exact requirements for requesting placement on Coinkite's compatible-wallet
pages are recorded in
`docs/qa/coinkite-wallet-list-readiness.md`. SATSCARD is functionally close but
still needs the complete current-production physical-card matrix. TAPSIGNER is
not eligible for a signing-wallet listing while PIN/CVC change and direct
transaction signing are missing.

## Release controls

- The Android manifest is checked for forbidden Bluetooth and direct-USB signer
  permissions/features.
- Hardware-wallet labels are checked so USB, Bluetooth, BLE, and Virtual Disk
  cannot silently return as supported Clench signer transports.
- The no-USB/no-Bluetooth policy is required in the signer picker, hardware
  settings, and privacy screen.
- The full deterministic hostile-input, release-key isolation, SBOM,
  provenance, signed-APK verification, and independent no-secrets rebuild
  controls from v0.3.22 remain in force.

## Physical-test boundary

The maintainer authorized publication on 2026-07-28 UTC with the physical
hardware matrix explicitly deferred for follow-up testing on the published
APK. SATSCARD, TAPSIGNER, Coldcard, SeedSigner, Keystone, Passport, Jade,
representative physical Android NFC/camera, hardware-backed Keystore,
biometric, upgrade, process-kill, and removable-media rows remain `NOT RUN`.

That deferral is not a pass. Simulator, emulator, local build, and hosted CI
results must not be described as real-device evidence. Physical results belong
in `docs/qa/physical-hardware-gates-v0.3.23.md` and must record the exact APK
hash, Android device/API, card/signer model and firmware, network, date, and
sanitized result.
